# 메뉴 옵션 시스템 구현 청사진 (Blueprint)

안녕하세요! 요청하신 내용을 바탕으로, 하드코딩된 더미 옵션을 제거하고 **실제 DB와 연동되는 유연한 메뉴 옵션 시스템**을 구축하기 위한 설계도를 작성했습니다. 구현에 들어가기 전, 이 설계도를 기반으로 논의하고자 합니다.

---

## 1. 데이터베이스 설계 (ERD)

관리자가 자유롭게 옵션을 추가하고 관리할 수 있도록, **옵션 그룹(Option Group)**과 **옵션 상세(Option Detail)** 테이블을 분리하여 설계합니다.

### A. 테이블 매핑
* **`menu_option_groups` (옵션 그룹)**
  * `id` (PK)
  * `menu_id` (FK): 어떤 메뉴의 옵션인지 매핑
  * `name`: 옵션명 (예: "온도", "사이즈", "얼음 양", "샷 추가")
  * `is_required`: 필수 선택 여부 (boolean) - 예: 온도는 필수(true), 샷 추가는 선택(false)
  * `is_multiple`: 중복 선택 가능 여부 (boolean) - 예: 단일 선택(라디오 버튼) vs 다중 선택(체크박스)
  * `sort_order`: 화면 노출 순서

* **`menu_option_details` (옵션 상세 항목)**
  * `id` (PK)
  * `option_group_id` (FK): 어느 그룹에 속하는지 매핑
  * `name`: 항목명 (예: "Hot", "Ice", "레귤러", "라지", "1샷 추가")
  * `additional_price`: 추가 금액 (예: 라지 +500, 샷추가 +500)
  * `sort_order`: 항목 노출 순서

> **💡 아이스 전용 옵션 처리 (얼음 양)**
> "얼음 양" 옵션은 사용자가 "온도"에서 "Ice"를 눌렀을 때만 활성화되게 할 수 있습니다. 
> 시스템을 너무 복잡하게 만들지 않기 위해, 관리자 화면에서는 그룹 이름으로 구분하고 프론트엔드 주문 팝업에서는 **"온도" 옵션의 값이 "Ice"일 경우에만 노출**하는 식의 클라이언트 로직을 추가하는 방향을 제안합니다.

## 2. 초기 데이터 (초기화 전략)

디저트/샌드위치는 옵션을 아예 비워두고, 기존 음료 메뉴들에 대해서만 `DataInitializer.java`를 수정하여 아래와 같이 테이블에 초기 데이터를 밀어넣겠습니다.

* **커피류 (아메리카노, 카페라떼, 카푸치노, 에스프레소, 시그니처 등)**
  1. 온도 (필수, 단일): Hot(+0), Ice(+0)
  2. 사이즈 (필수, 단일): Regular(+0), Large(+500)
  3. 얼음 양 (선택, 단일, 아이스 전용): 적게(+0), 보통(+0), 많이(+0)
  4. 샷 추가 (선택, 다중): 1샷 추가(+500), 2샷 추가(+1000)

* **단맛이 들어간 음료 (카라멜 마끼아또, 바나나 라떼)**
  * 위 커피류 옵션 + **시럽 선택 (선택, 다중)**: 바닐라 시럽(+500), 헤이즐넛 시럽(+500), 카라멜 시럽(+500)

* **디저트 & 샌드위치 (쿠키, 케이크, 무스, 샌드위치 등)**
  * 옵션 없음 (빈 리스트)

## 3. 프론트엔드 UI 변경 사항

### 🧑‍💻 관리자 (Admin) 화면
1. **메뉴 등록/수정 폼 (`/admin/menus/new`, `/admin/menus/[id]/edit`)**
   * 기존 하드코딩된 `OptionManager`를 완전히 개편합니다.
   * 관리자가 [+ 옵션 그룹 추가] 버튼을 눌러 위에서 설계한 항목(`옵션명`, `필수여부`, `단일/다중선택`)을 만들 수 있게 합니다.
   * 각 그룹 안에 하위 요소(`상세 항목명`, `추가금액`)를 동적으로 추가/삭제할 수 있는 UI를 구성합니다.
2. **메뉴 상세 (`/admin/menus/[id]`)**
   * 현재 메뉴에 매핑된 옵션이 어떤 것들이 있는지, 추가 금액은 얼마인지 트리 또는 표 형태로 깔끔하게 보여줍니다.

### 👩‍🦰 사용자 (Customer) 화면
1. **메뉴 상세 보기 / 장바구니 담기 팝업 (`/menus/[id]`, 홈 팝업)**
   * 메뉴 카드를 누르거나 [장바구니 담기] 버튼을 누르면, **옵션 선택 모달(팝업)**이 뜹니다.
   * 관리자가 DB에 저장한 옵션 그룹과 상세 항목들이 렌더링됩니다.
   * **필수 옵션**을 모두 선택해야만 [장바구니 담기] / [결제하기] 버튼이 활성화됩니다.
   * 온도에서 "Ice"를 선택해야만 "얼음 양" 옵션이 나타나게 하는 로직을 반영합니다.
   * 선택한 옵션에 따라 "총 예상 금액"이 실시간으로 하단에 계산됩니다.

2. **장바구니 로직 (`cart_items` 테이블)**
   * (현재) 멤버 ID와 메뉴 ID만으로 장바구니를 구분하고 있습니다.
   * (변경) 장바구니 테이블에 **선택한 옵션 정보를 담을 컬럼(JSONB 타입 또는 별도 상세 테이블)**이 추가되어야 합니다. 그래야 "Hot 아메리카노"와 "Ice 아메리카노"가 장바구니 안에서 서로 다른 품목으로 구분될 수 있습니다.

## 4. 진행 순서 (Action Plan)

안전한 구현을 위해 다음 순서로 작업을 쪼개서 진행할 예정입니다.

1. **Phase 1: 백엔드 DB 설계 & 엔티티 생성**
   * `MenuOptionGroup`, `MenuOptionDetail` JPA Entity 선언
   * 장바구니(`CartItem`) 테이블 구성을 옵션까지 반영 가능하게 확장
2. **Phase 2: DB 초기화 (초기 데이터 삽입)**
   * `DataInitializer`에 커피/음료별 옵션 세팅 코드 추가
3. **Phase 3: 관리자 API 및 프론트엔드 연동**
   * 메뉴 등록 시 옵션 데이터도 저장할 수 있도록 DTO 수정
   * 관리자 옵션 등록 UI 완료
4. **Phase 4: 사용자 화면 구현**
   * 사용자 팝업 모달 UI 및 실시간 금액 계산 로직 추가
   * 장바구니 담기 API 호출 시 옵션 정보도 전송

---
